## 1.3.0

- NetherNet before Bedrock 26.60 (27 October 2026, no RakNet any more): every Geyser (proxy, single server, Standalone) runs `transport: both` with its own UDP port for WebRTC, chosen without collisions (other Geyser, Bedrock servers, public ports, router forwardings, a taken TCP port). Existing configs are switched by themselves – soon after the start, in the self-maintenance and right before every start; a running Geyser restarts when nobody plays (Standalone alone). What you set on purpose stays (own port, `nethernet`, `raknet` set back by hand). / NetherNet vor Bedrock 26.60 (27. Oktober 2026, kein RakNet mehr): Jeder Geyser (Proxy, Einzelserver, Standalone) läuft mit `transport: both` und eigenem UDP-Port für WebRTC, gewählt ohne Überschneidung (anderer Geyser, Bedrock-Server, öffentliche Ports, Router-Freigaben, belegter TCP-Port). Vorhandene Konfigs stellt Hostwerk selbst um – kurz nach dem Start, in der Selbstwartung und direkt vor jedem Start; ein laufender Geyser startet neu, wenn niemand spielt (Standalone allein). Was du bewusst eingestellt hast, bleibt (eigener Port, `nethernet`, von Hand zurück auf `raknet`).
- Firewall and router: TCP on the Bedrock port (signaling) and the new UDP port; “Addresses for friends” says which ports have to be open – friends still type in only address and port. / Firewall und Router: TCP auf dem Bedrock-Port (Anmeldung) und der neue UDP-Port; „Adressen für Freunde“ sagt, welche Ports offen sein müssen – Freunde geben weiterhin nur Adresse und Port ein.
- “NetherNet ready” on the Geyser cards once Geyser’s signaling answers (`GET /v1/join`, checked once per start), with a short explanation; Geyser older than build 1237, no answer or RakNet by hand show up there and as one bundled line in the self-maintenance. / „NetherNet bereit“ auf den Geyser-Karten, sobald Geysers Anmeldung antwortet (`GET /v1/join`, einmal je Start geprüft), mit kurzer Erklärung; Geyser älter als Build 1237, keine Antwort oder von Hand RakNet erscheinen dort und als eine gebündelte Zeile in der Selbstwartung.
- Checked against the real Geyser 2.12.0 (build 1269) at Velocity and as Standalone: config taken over, signaling answers, WebRTC port bound, RakNet still answers. / Gegen den echten Geyser 2.12.0 (Build 1269) an Velocity und als Standalone geprüft: Konfig übernommen, Anmeldung antwortet, WebRTC-Port belegt, RakNet antwortet weiter.

## 1.2.0

- Geyser Standalone for Java servers without plugin support (Vanilla, Forge, own JARs, Forge modpacks): Geyser runs as its own program in front of the server, starts and stops with it, keeps itself up to date with a probe and a way back (only Geyser restarts, the Java server keeps running). Honest about the limits: without Floodgate, Bedrock players need a Java account. / Geyser Standalone für Java-Server ohne Plugin-Unterstützung (Vanilla, Forge, eigene JARs, Forge-Modpacks): Geyser läuft als eigenes Programm vor dem Server, startet und stoppt mit ihm, hält sich mit Probe und Rückweg selbst aktuell (nur Geyser startet neu, der Java-Server läuft weiter). Ehrlich zu den Grenzen: ohne Floodgate brauchen Bedrock-Spieler ein Java-Konto.
- Bedrock Dedicated Server as a server type of Hostwerk’s core (Hostwerk 3.x): new Bedrock servers are created there (console, settings, worlds, backups, allow list and permissions, updates with a way back); servers of this extension move there with one click – same worlds, same ports. Older Hostwerk keeps the extension’s own way. / Bedrock Dedicated Server als Servertyp im Kern von Hostwerk (Hostwerk 3.x): neue Bedrock-Server entstehen dort (Konsole, Einstellungen, Welten, Sicherungen, Erlaubnisliste und Rechte, Updates mit Rückweg); Server dieser Erweiterung ziehen mit einem Klick um – gleiche Welten, gleiche Ports. Älteres Hostwerk behält den eigenen Weg der Erweiterung.
- Fixes found with the real programs: the Floodgate config now starts from Floodgate’s own template (the short one of 1.0/1.1 made Floodgate fail – Geyser then switched itself off; existing ones are repaired at start, values stay); ping passthrough on Velocity 4 goes into its `[ping-passthrough]` section (a top-level key made Velocity refuse the whole velocity.toml); the BungeeCord download is checked against the MD5 Jenkins computes for the archived file (the build’s fingerprint list never matched, so BungeeCord could not be installed); a BungeeCord network without servers gets a closed placeholder (BungeeCord does not start with an empty list). / Mit den echten Programmen gefundene Fehler behoben: Die Floodgate-Konfig entsteht jetzt aus Floodgates eigener Vorlage (die kurze aus 1.0/1.1 ließ Floodgate scheitern – Geyser schaltete sich dann ab; vorhandene werden beim Start repariert, Werte bleiben); Ping-Durchreichen landet bei Velocity 4 im Abschnitt `[ping-passthrough]` (ein Schlüssel ganz oben ließ Velocity die ganze velocity.toml ablehnen); der BungeeCord-Download wird gegen die MD5 geprüft, die Jenkins für die archivierte Datei berechnet (die Fingerabdruck-Liste des Builds passte nie, BungeeCord ließ sich nicht installieren); ein BungeeCord-Netzwerk ohne Server bekommt einen geschlossenen Platzhalter (BungeeCord startet mit leerer Liste nicht).
- Tested against the real programs (Velocity, Geyser, Floodgate, BungeeCord, Geyser Standalone): Geyser’s bind address and target can be set (`address`, `remoteAddress`, `remotePort`), `auth-type: offline` for offline servers; Bedrock servers of the core are never offered Geyser and their UDP ports are kept free. / Gegen die echten Programme geprüft (Velocity, Geyser, Floodgate, BungeeCord, Geyser Standalone): Bind-Adresse und Ziel von Geyser einstellbar (`address`, `remoteAddress`, `remotePort`), `auth-type: offline` für Offline-Server; Bedrock-Servern des Kerns wird kein Geyser angeboten, ihre UDP-Ports bleiben frei.

## 1.0.0

- First version: one place for everything around several Minecraft servers and platforms. Replaces “Bedrock bridge” and the Minecraft part of “Game server network”. / Erste Fassung: ein Ort für alles rund um mehrere Minecraft-Server und Plattformen. Löst „Bedrock-Brücke“ und den Minecraft-Teil von „Spiele-Server-Verbund“ ab.
- Networks with Velocity (modern forwarding, through Hostwerk’s core) or BungeeCord (new server type through SDK 3.2): lobby, order, forced hosts, maintenance per server, MOTD, icon, player count, ping passthrough, start/stop in order, checks, addresses. / Netzwerke mit Velocity (modern forwarding, über Hostwerks Kern) oder BungeeCord (neuer Servertyp über SDK 3.2): Lobby, Reihenfolge, forced hosts, Wartung je Server, MOTD, Symbol, Spielerzahl, Ping durchreichen, Starten/Stoppen der Reihe nach, Prüfung, Adressen.
- Shared whitelist, operators and bans for the whole network (Java through Mojang, Bedrock through the Floodgate prefix); moving players between servers. / Gemeinsame Whitelist, Operatoren und Sperren für das ganze Netzwerk (Java über Mojang, Bedrock über den Floodgate-Vorsatz); Spieler zwischen Servern verschieben.
- Bedrock: Geyser + Floodgate once on the proxy (one key for every server, created by Hostwerk before the first start), on a single server, or Mojang’s Bedrock Dedicated Server. Geyser’s new config layout (2.9+) is understood. / Bedrock: Geyser + Floodgate einmal am Proxy (ein Schlüssel für alle Server, von Hostwerk vor dem ersten Start angelegt), auf einem einzelnen Server oder Mojangs Bedrock Dedicated Server. Geysers neues Konfigurationsformat (2.9+) wird verstanden.
- Version bridges ViaVersion/ViaBackwards/ViaRewind on every server behind the proxy. / Versions-Brücken ViaVersion/ViaBackwards/ViaRewind auf jedem Server hinter dem Proxy.
- Without maintenance: Geyser/Floodgate, proxy builds and Bedrock Dedicated Server update themselves when nobody is online – with checksums, compatibility check, probe and a way back. / Ohne Wartung: Geyser/Floodgate, Proxy-Builds und Bedrock Dedicated Server aktualisieren sich, wenn niemand online ist – mit Prüfsumme, Verträglichkeitsprüfung, Probe und Rückweg.
- Moving over from the Bedrock bridge without loss: same data, same port, same Floodgate key; Geyser behind a proxy moves onto the proxy with one click. / Umzug aus der Bedrock-Brücke ohne Verlust: gleiche Daten, gleicher Port, gleicher Floodgate-Schlüssel; Geyser hinter einem Proxy zieht mit einem Klick auf den Proxy.
